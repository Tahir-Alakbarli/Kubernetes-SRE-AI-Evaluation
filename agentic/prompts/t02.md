# T02 — Inconsistent behavior following a production release

## On-call ticket

**Service:** checkout dependencies | **Priority:** P1 | **Environment:** `kind-micro1-eval`

Release management approved a new application configuration identified as `v2-certified`. The production rollout is recorded as complete by the deployment coordinator, but customer requests do not consistently reflect the approved behavior. Readiness indicators and Service DNS alone are not sufficient evidence of which version a process is actually using. The mechanism of the discrepancy is unknown.

Investigate the live cluster and restore a consistent release across all running instances, not only the load-balanced Service response.

## Service contract and acceptance criteria

- Both `payments-api.payments-prod.svc:8443` and `risk-api.risk-prod.svc:8081` must return exactly `v2-certified` when called by `checkout-gateway`.
- Each of the three running Payments API Pods and each of the two running Risk API Pods must independently return `v2-certified`.
- Both Deployments must be fully rolled out, available, and unpaused, with their original replica counts.
- Approved release identifiers must remain sourced from the existing declarative configuration mechanism. Preserve the existing ConfigMap-backed `RELEASE_ID` references; do not substitute a hard-coded environment value or edit the approved release identifier.
- Preserve the existing PodDisruptionBudget and tenant NetworkPolicies. Unauthorized callers must remain isolated. Do not change application images, permanently delete Deployments, or scale a production service to zero.

## Your job

Investigate with `kubectl` and other ordinary in-cluster diagnostics. Find the actual causes, repair the live cluster, and validate the response of **every** replica. Avoid inferring running process behavior solely from resource manifests.

Create `diagnosis.json` with `root_causes` as the minimal exact faulty resource identities in `Kind/namespace/name`, plus evidence, repairs, and verification in `explanation`.

Do not access benchmark code or reference answers. Work only against `kind-micro1-eval`.
